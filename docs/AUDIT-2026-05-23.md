## 2. Genuine Open Bugs — Confirmed by Code Inspection

These match what STATUS.md says. No discrepancy, just confirmation they are real and unfixed.

### CONFIRMED: BUG-01 — `vec_memory` integer PK crash (CRITICAL)

The `recall()` path in `src/agent/memory.ts` looks correct (joins on `rowid`). The crash fires
on **store**, not recall. The `store()` method is almost certainly passing a UUID string as the
`vec_memory` primary key instead of an integer.

**Fix (exact):**
- The `vec_memory` table must receive an integer PK. Use the `rowid` returned after inserting
  into `vector_memory_data`, then pass that integer to the `vec_memory` insert.
- Pattern:
  ```typescript
  const { lastInsertRowid } = db.prepare("INSERT INTO vector_memory_data ...").run(...);
  db.prepare("INSERT INTO vec_memory(rowid, embedding) VALUES (?, ?)").run(lastInsertRowid, embedding);
  ```
- Do NOT use `AUTOINCREMENT` on `vec_memory` itself — sqlite-vec virtual tables don't support it.
  Always derive the PK from the data table's `rowid`.

This is still the top priority. Fix before anything else.

### CONFIRMED: BUG-05 — `FileCoordinator.requestAccess()` result ignored in Orchestrator

`FileCoordinator` has SQLite backing (Gap 4 genuinely closed), but `Orchestrator.ts` does not
check the `allowed` field before dispatching. The lock is advisory-only.

**Fix:** In `src/orchestrator/Orchestrator.ts`, wherever tasks are dispatched:
```typescript
const result = await this.fileCoordinator.requestAccess(task.id, task.artifacts);
if (!result.allowed) {
  // requeue with backoff, do not dispatch
  await this.requeueWithBackoff(task, result.conflicts);
  return;
}
// proceed with dispatch
```
Implement `requeueWithBackoff()` with exponential delay (start 500ms, max 30s).
